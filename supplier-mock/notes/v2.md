# Supplier API v2: inventory reports on-hand and reserved units

Endpoint: `GET /v1/inventory/{sku}`

**Breaking.** The top-level `stock` field is removed. It is replaced by an `inventory` object:

```json
{ "inventory": { "on_hand": 7, "reserved": 5 } }
```

- `inventory.on_hand`: units physically in the warehouse, including units already promised to open orders.
- `inventory.reserved`: units held for open orders. These cannot be sold.

**What changed in meaning.** The old `stock` field reported the units available to sell. v2 no longer reports that number directly; it reports what is in the warehouse and what is already promised, and clients that need available stock work it out from those two fields. During backorders, `reserved` can be higher than `on_hand`. A SKU in that state has nothing available to sell.

The fields `sku`, `warehouse` and `updated_at` are unchanged.
